## New items

### 1. Claude Code Projects (beta) — coordinator + parallel threads + shared memory
- **Source**: [Projects redesigned: from folder to conversation](https://claude.com/blog/projects-redesigned), Anthropic, 2026-09-17
- **Pattern**: A project now has a coordinator agent that scopes an incoming request, delegates work to parallel cloud "threads" (each on its own branch, potentially in a different repo), reviews their outputs, and assembles the final result. Threads share memory and a project-level library of files/artifacts across repos and sessions.
- **Parity impact**: New row added under §1 Loop primitives. This is the first first-party productization of "many coordinated agent runs sharing memory across a project" — squarely adjacent to gooseherd's `/orch` (single coordinated run) and `/arena` (blind parallel comparison, no shared memory). gooseherd has ❌ here: no persistent project layer, no cross-run shared memory. See "Pick of the week" below.

### 2. Claude Code — Auto Mode becomes the default permission mode
- **Source**: Claude Code changelog (v2.1.275–2.1.278, `github.com/anthropics/claude-code/blob/main/CHANGELOG.md`); default flip announced 2026-08-07, live 2026-08-14 for Pro/Max/Team.
- **Pattern**: A classifier model auto-approves actions that don't escalate scope, target unrecognized infrastructure, or look injection-driven; `permissions.deny`/`permissions.ask`, written as plain-English sentences, take priority over the classifier. This replaces "review every command" with "write a few sentences of policy, get classifier-gated auto-approval."
- **Parity impact**: Updated the existing "Permission allowlists" row (§4). gooseherd has `GOOSE_ORCH_ALLOWED_COMMANDS`/`allowlist`, but it only gates the headless `/orch` implementer role — there's no general, user-facing permission system, let alone natural-language rules or classifier gating. Still ❌, bar is now higher than the v1.43 allowlist plan already on the roadmap.

### 3. Codex — `codex queue` command for messaging existing sessions
- **Source**: Codex changelog (`developers.openai.com/codex/changelog`), ~August 2026.
- **Pattern**: Lets a user push a message into an already-running local or remote Codex session/task instead of waiting for it to finish. Also shipped alongside: an interactive agents dashboard (search/start/open/rename/stop tasks) and TUI `/cd`, `/pwd`, `/cwd`.
- **Parity impact**: Updated "Message queueing while a turn streams" (Codex ❌ → 🔶, needs verification on whether it queues mid-turn like CC's interactive queueing) and added a new "Task/agent dashboard" row (§4) — gooseherd has `GOOSE_MAX_BACKGROUND_TASKS` but no listing/management surface for those tasks; codebase search this week found none.

### 4. Claude Code — bare `AGENTS.md` support
- **Source**: Claude Code changelog, v2.1.277 (~Aug/Sep 2026).
- **Pattern**: When a project has no `CLAUDE.md`, Claude Code now reads `AGENTS.md` directly. Minor, but confirms `AGENTS.md` as the converging cross-vendor convention gooseherd already standardized on.
- **Parity impact**: Note-only addition to the existing ✅/✅/✅ "Memory" row (§4) — no status change.

## Pick of the week

**/orch task**: *Add a project-level shared memory file that `/orch` runs read and append to, so sequential runs in the same repo can see prior runs' task descriptions, verdicts, and touched files.*

Scope: on `/orch` completion, append a JSON line (task, verdict, model mix, files touched, timestamp) to `.goose/project-memory.jsonl` at the repo root (git-ignored, alongside `orch_ledger.jsonl`); on `/orch` start, load the last N (default 5) entries and inject a short summary into the planner's context so it knows what recent runs already tried.

**Success criterion**: an integration test runs two sequential `/orch` tasks against the same throwaway repo; after the second run, assert that the planner's recorded prompt/context for that run contains the first run's task description and verdict verbatim, and that `.goose/project-memory.jsonl` has exactly 2 entries with valid JSON on each line.

This is the smallest slice of the Claude Code Projects gap that fits one `/orch` cycle — it doesn't attempt the coordinator/parallel-threads part, just the shared-memory primitive those threads depend on, which is also the piece most directly reusable by a future `/arena`-with-memory or multi-repo coordinator.
