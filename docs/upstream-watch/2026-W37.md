## Pick of the week

**Add unused-skill detection to `goose skills list`, matching the half of CC's `/skill-doctor` gooseherd doesn't have yet.**

`goose skills list` (`crates/goose-cli/src/commands/skills.rs`) already computes and prints, per loaded skill, a description-token count and a content-token count — the context-cost half of `/skill-doctor` is done. What's missing is flagging skills that loaded but were never actually invoked during the session, the way CC's `/skill-doctor` does.

Ready-to-run `/orch` task:

> In `crates/goose-cli/src/commands/skills.rs`, extend `goose skills list` with a `--doctor` flag (or a `goose skills doctor` subcommand — pick whichever fits the existing command structure better) that, for the *current or most recent* session, cross-references the set of loaded skills against skill-invocation events already visible to the CLI (check whether skill dispatch already emits a trackable event; if not, add a minimal per-session invocation counter keyed by skill name at the point a skill is dispatched). Output must list, for each loaded skill, its existing token-cost figures plus a new "used" / "unused this session" flag.
>
> Success criterion: a new unit test in `crates/goose-cli/src/commands/skills.rs` that loads a fixture set of N skills, records invocation events for a strict subset of size M < N, runs the doctor report, and asserts the output flags exactly `N - M` skills as unused and `M` as used, with the existing token-count fields unchanged for all N. `cargo test -p goose-cli` passes.

(The bigger, previously-deferred gap — a `--restricted`-style hard-lockdown session mode — is still open and still not this week's pick; it needs a pass through the ACP permission policy engine, which is a bigger unit of work than a single cycle. Flagging again so it isn't forgotten.)
