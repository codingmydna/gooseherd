## New items

### 1. Auto mode becomes the default permission mode
- **Date:** 2026-08-14 (shipped as research preview 2026-03-23, GA'd as default this window)
- **Link:** https://code.claude.com/docs/en/permission-modes ,
  digest: https://code.claude.com/docs/en/whats-new/2026-w32
- **Pattern:** a second, cheaper model runs as a real-time safety classifier over every
  risky tool call (writes, shell, network), replacing manual per-action approval. Anthropic's
  own numbers (cited in the docs): the classifier catches ~89% of planted dangerous commands
  vs. ~14% for human reviewers rubber-stamping prompts (people were approving 97% of prompts
  before the change).
- **Parity impact:** new row in `docs/parity.md` §4. This is "small-model routing" applied to
  *safety judgment* rather than cost — a different axis than gooseherd's planner/implementer
  split. gooseherd's closest analog (`GOOSE_ORCH_IMPLEMENT_POLICY=allowlist` for headless orch,
  plus the `permission.yaml` tool-level allow/ask/deny rules already in the codebase) is static
  configuration, not a per-action model judgment call, and neither applies to interactive
  sessions outside `/orch`.

### 2. `claude plugin eval` — skill/plugin eval harness with a no-plugin baseline
- **Date:** ~2026-09-10 (requires Claude Code v2.1.269+; the docs' own example timestamp is
  2026-09-10)
- **Link:** https://code.claude.com/docs/en/plugin-evals
- **Pattern:** `claude plugin eval init` proposes graded test cases for a skill/plugin, then
  `claude plugin eval .` runs each case 3× *with* the plugin loaded and 3× *without*, scoring
  both arms and reporting `WITH` / `W/OUT` / `Δ`. A judge-graded rubric, a tool-call check, or a
  regex can each be a grader; CI can gate on the score.
- **Parity impact:** new row in `docs/parity.md` §2. gooseherd has exemplar/playbook uplift
  (`GOOSE_PLAN_EXEMPLARS_INJECT`, `GOOSE_ORCH_PLAYBOOK`) but no equivalent ablation — nothing
  measures "did the playbook actually help on this task" the way CC's `Δ` does. See Pick of the
  week below.

### 3. Codex Automations — scheduled + event-triggered background runs with thread continuity
- **Date:** rolling out through 2026-08/09 (exact GA date unconfirmed — corroborated by
  multiple outlets, not a direct OpenAI fetch)
- **Link:** https://developers.openai.com/codex/app/automations (unreachable this run —
  re-verify directly)
- **Pattern:** Codex Automations combine an instruction + optional skills with either a time
  schedule or an event trigger (Gmail, Slack, GitHub events on some plans since 2026-08-25).
  A run can now resume its own thread later with original context intact, and finished runs
  land in a review queue rather than silently completing. OpenAI describes using this
  internally for daily issue triage, CI-failure summaries, and release briefs — i.e. exactly
  the "proactive loop" pattern from the original loops taxonomy.
- **Parity impact:** `docs/parity.md` §1 "Proactive loop" row: Codex moves from 🔶 to ✅
  (both upstreams now ship this natively). gooseherd stays ❌ — the composition (cron +
  headless `goose orch`/`goose loop` + a goal condition) is possible today but requires the
  user to wire the trigger and the resume logic themselves; there's no first-class "wake on
  event, resume this thread" primitive.

## Pick of the week

The plugin-eval ablation pattern (#2) is the best-scoped, single-week win: gooseherd already
has the exact infrastructure CC's `Δ` needs (isolated worktrees via `/arena`, the
`orch_ledger.jsonl` schema, and env-var-gated uplift knobs like `GOOSE_ORCH_PLAYBOOK`) — this
is wiring, not new architecture.

```
/orch add an `--ablation KNOB=on,off` flag to `goose arena` that runs the same task twice in
isolated worktrees with the named environment variable pinned to each value in turn, then
appends both runs' cycle count and reviewer verdict to orch_ledger.jsonl with a new `ablation`
field recording the knob and value used. Reuse arena's existing worktree/timeout/ledger code
paths — no new gate or scheduling logic.

Success criteria (numeric/checkable):
1. `cargo test -p goose-cli` passes with no new warnings under `cargo clippy --workspace
   --all-targets -- -D warnings`.
2. Running `goose arena --ablation GOOSE_ORCH_PLAYBOOK=always,never "<task>"` against this
   repo on 3 sample tasks produces 2 ledger rows per task (6 total), each tagged with its
   `ablation` value, and at least 1 of the 3 tasks shows a different `cycles` or `verdict`
   between the `always` and `never` rows.
```
