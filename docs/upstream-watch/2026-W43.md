## New items

### 1. Claude Code changelog 2.1.297–2.1.303 — the "auto mode" cluster
Seven versions since last week's cutoff (2.1.296). The notable thread across them is auto mode
(the client-side classifier that decides which model/effort handles a turn without the user
picking):
- **2.1.299**: `/effort` and `/fast` surfaced directly in the agent view; idle compaction in the
  terminal; `--shutdown-drain-sec` for the self-hosted orchestrator.
- **2.1.301**: new OpenTelemetry attributes specifically for auto-mode classifier decisions
  (telemetry, not a new control surface).
- **2.1.302**: `CLAUDE_CODE_AUTO_MODE_MODEL` — lets an org pin which model the auto-mode
  classifier itself runs on, separate from the model it ends up routing a turn to.
- 2.1.297/298/300/303: largely fixes (cloud sessions, MCP, worktrees, Claude Tag) and minor
  additions (cache-lifetime telemetry, `/advisor` on AWS).

**Pattern:** a dedicated classifier that decides, per turn, which model and effort level should
handle it — distinct from gooseherd's existing "expensive planner, cheap implementer" loop
primitive, which is a deliberate role split *within* a run, not an automatic per-turn routing
decision made *for* the user.

**Parity impact:** new row under Daily-driver table stakes. gooseherd has manual switching
(`/roles`, `/preset`) and a related-but-distinct automation — `GOOSE_ORCH_PLAYBOOK=auto` picks a
frontier-pattern playbook, not a per-turn model/effort decision. Marked ❌ for gooseherd; not
picked as this week's gap (see below) because it's additive UX polish, not a structural gap.

### 2. Code Review is now generally available — [post](https://claude.com/resources/articles/code-review-is-now-generally-available) (2026-10-15)
Code Review (automated PR review before a human looks) left research preview for Claude Team/
Enterprise orgs. Vs. the preview: ~3x faster (20 min → 6–10 min), fewer low-value findings, and
each repo can be set to Quick/Standard/Deep review depth. A companion post, "How the Claude Code
team does code review" (2026-10-16), was linked from the same blog listing but returned HTTP 404
on both the `claude.com` and `claude.dev` URLs tried — its content is not included here since it
couldn't be verified first-hand.

**Pattern:** tiered review depth as a deliberate cost/thoroughness dial, same shape as choosing
an effort level.

**Parity impact:** No status change — gooseherd's `/code-review` skill already has the same
Quick/Standard/Deep shape via `--effort low|medium|high|xhigh|max`. Noted as validation on the
existing "Independent second-pass review" row.

### 3. Agent observability on the Claude Platform — [post](https://claude.com/resources/articles/agent-observability-on-the-claude-platform) (2026-10-14)
Every agent turn, model call, and tool/MCP call now exports as a standard OpenTelemetry trace
(GenAI semantic conventions) — latency, token counts, step IDs — so traces drop into Grafana,
Honeycomb, Datadog, or Langfuse without custom glue. Framed as both debugging and
cost/usage-anomaly tracking across a team.

**Parity impact:** checked the repo before writing this row — gooseherd already ships real OTLP
trace/metric/log export (`crates/goose/src/otel/otlp.rs`), on top of `orch_ledger.jsonl` +
`/stats`. Row stays ✅; added a "needs verification" note on whether gooseherd's span/attribute
names specifically match the OTel **GenAI semantic conventions** CC cites (same transport,
unconfirmed whether the shape matches well enough to drop into the same dashboards unmapped).

## Pick of the week

**Highest-leverage gap: no proactive loop (scheduled/event-triggered agent run with no human in
the loop) as a first-class gooseherd primitive.**

This gap has been flagged twice without being picked (raised as a side-effect of the Block
production-usage citation in both [2026-W41](2026-W41.md) and [2026-W42](2026-W42.md)). It's
picked this week in part because this very digest is a live demonstration of the pattern: a
cron-fired session that reads current state, decides what changed, and opens a PR with no human
watching — exactly the shape Block runs in production and exactly what `/schedule` + `/goal`
composition gives Claude Code users today. gooseherd can only approximate it today with a raw
external cron entry calling `goose orch -t --max-cycles`; there's no first-class way to say "run
this goal-loop on a schedule" from inside gooseherd itself.

Ready-to-run `/orch` task description:

> Add a `goose orch --schedule <cron-expr>` mode (or a thin `goose schedule add <cron-expr> --
> goose orch ...` subcommand) that registers a recurring headless `/orch` run via the host
> scheduler (cron on Linux/macOS, Task Scheduler on Windows), persists its own run history to
> `orch_ledger.jsonl` tagged with a `schedule_id`, and exposes `goose schedule list/remove`. Each
> fire is a normal headless orch run (goal condition + `--max-cycles`) with no human in the loop
> unless the reviewer's VERDICT is ambiguous, in which case it should fail closed (skip the cycle,
> log to the ledger, don't guess). Success criterion: `goose schedule add "*/5 * * * *" -- goose
> orch -t "report test failures" --max-cycles 1` registers a job that fires at least 3 times in 15
> minutes in a test harness using a fake clock/mock scheduler, each fire producing exactly one new
> `orch_ledger.jsonl` entry tagged with the same `schedule_id` — verified by a new integration test
> in `crates/goose-cli/src/session/orchestrate/` asserting ledger entry count equals fire count.
