## New items found

### 1. [Building verification loops in Claude Code with skills](https://claude.com/blog/building-verification-loops-in-claude-code-with-skills) — Claude Code team, 2026-07-22

**Pattern:** Names two verification shapes — *standalone* skills (deliberately invoked, cross-cutting checks like pre-commit security scans or a11y audits that don't apply every time) and *embedded* verification (fires automatically as part of the producing skill, e.g. a `/verify` skill that builds, runs, and observes the app). Recommends definitive, checkable rules ("reject migrations that drop columns without a backfill") over vague criteria. Also mentions a Code Review research-preview feature that runs automated review passes on 100% of enabled-repo PRs.

**Parity impact:** Updates §2 "Verification skills" row in `parity.md`. gooseherd's `.goose-gates.yaml` machine gates are structurally the "embedded, automatic" half of this taxonomy already. The "standalone, deliberately invoked, named skill with numeric pass/fail" half is still missing — playbooks exist but aren't structured for it. Row stays 🔶, note rewritten to point at the taxonomy.

### 2. [Auto mode is now the default in Claude Code for Pro, Max, and Team plans](https://claude.com/blog/auto-mode-default-in-claude-code) — Claude Code team, 2026-08-07

**Pattern:** Replaces repeated manual approval prompts with a classifier that judges each tool call for irreversible/destructive/out-of-bounds risk, falling back to a safer route or an explicit ask when it blocks something. Anthropic's tester study: 89% dangerous-command catch rate for the classifier vs. 13.6% for manual human review. Classifier token overhead is no longer billed separately.

**Parity impact:** New pattern, no existing row. Added "Learned permission classifier" row to §4. gooseherd's two permission layers (Plan-Explore tool-kind policy, orch implement allowlist) are both static rule sets — no learned judge. Marked ❌, not urgent (Codex doesn't do this either, favors OS sandboxing), but flagged as the pick of the week below.

## Pick of the week

**Gap:** gooseherd's `/orch` implementer permission layer is 100% static (tool-kind policy in Plan-Explore mode; command allowlist in headless orch/arena). Claude Code's new auto-mode classifier catches 89% of dangerous commands vs. 13.6% for manual review, at near-zero extra cost. gooseherd has no equivalent judged-risk layer for the implementer role, which is the one role gooseherd deliberately hands write access to.

**Ready-to-run `/orch` task:**

> Build a small permission-risk classifier for the `/orch` implementer's shell-tool calls, callable from the ACP permission-decision path in `crates/goose/src/acp/provider.rs` alongside the existing allowlist check. Assemble a labeled bench of at least 40 shell commands split evenly between "safe" (e.g. `cargo test`, `git diff`, `npm run lint`) and "dangerous" (e.g. `rm -rf`, `git push --force`, credential exfiltration patterns, curl-pipe-to-shell) drawn from gooseherd's own SECURITY.md threat model and the allowlist's existing rejection list. Success criterion: the classifier catches **at least 90% of the dangerous commands** in the bench while flagging **no more than 10% of the safe commands** as risky, measured by a `cargo test` suite asserting on the labeled set.
