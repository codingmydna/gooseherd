## Pick of the week

**Close the frontier-model-currency gap: get `claude-opus-5` and the GPT-5.6 tier (`sol`/`terra`/`luna`) resolvable in gooseherd's model registry.**

Why this one over the Codex Security CLI gate (the runner-up): gooseherd's entire premise is "expensive frontier model plans and reviews, cheap models implement." Opus 5 became Claude Code's default Opus model on 2026-07-24, and GPT-5.6 reached general availability on 2026-07-09 with GPT-5.4 now deprecating 2026-08-31. If gooseherd's `/orch --planner-model` / `--reviewer-model` can't resolve these IDs, the harness silently can't use the current frontier tier for the one role that most needs it — a functional gap, not a cosmetic one. It's also the cheapest gap to close this week: additive JSON entries plus a resolution test, versus writing and testing a new gate recipe end-to-end.

Ready-to-run `/orch` task description:

Update `canonical_mapping_report.json` if it's derived from the model list. Success criteria (all must hold): (1) `cargo test -p goose-provider-types` passes with zero new failures; (2) a new unit test resolves each of the 4 new canonical IDs (`claude-opus-5`, `gpt-5.6-sol`, `gpt-5.6-terra`, `gpt-5.6-luna`) through the registry lookup used by `/orch --planner-model`/`--reviewer-model`/`--implementer-model` and asserts a non-`None` result; (3) `cargo clippy --workspace --all-targets -- -D warnings` is clean.
