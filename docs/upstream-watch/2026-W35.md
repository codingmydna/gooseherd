## New items since 2026-07-07

### 1. Cross-session agent messaging (Claude Code)
- **What**: `SendMessage` + `ListAgents` let one Claude Code session discover and message another by name — subagents in the current session, other local sessions (including background ones), and (with Remote Control) sessions on other machines/the web. `notify_when_idle` (opt-in, one-shot) asks a session to ping back when it next goes idle, so you stop polling.
- **Shipped**: incrementally — v2.1.224 (Aug 7, base SendMessage/ListAgents), v2.1.232 (Aug 13, `@`-mention addressing), v2.1.236 (Aug 19, `notify_when_idle`).
- **Docs**: https://code.claude.com/docs/en/cross-session-messaging
- **Pattern**: this is a new loop primitive — coordination *between* independently-running agent loops, not just within one. It turns "start a background job, come back later" into "start a background job, get pinged."
- **Parity impact**: added as a new row in section 1 of `docs/parity.md`. gooseherd already has a comparable tool surface — `ListSessions` / `StartAgent` / `SendMessage` / `InterruptAgent` / `ViewSession` in `crates/goose/src/agents/platform_extensions/orchestrator.rs` — but I could not verify from the code alone whether it discovers sessions across *separate* `goose` process invocations (CC's model) or is scoped to sub-agents spawned inside one `AgentManager`. Marked 🔶 needs-verification rather than claiming ✅. No `notify_when_idle` equivalent found.
