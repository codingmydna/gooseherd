## New items

### 1. Claude Code Mods — [Customize Claude Code with mods](https://claude.com/blog/claude-code-mods) (2026-10-01)
Mods are plugin-shipped TypeScript functions that go beyond hooks: they can rewrite
a prompt before it reaches the model, block/rewrite/retry tool calls, approve or deny
permissions, redact secrets from tool output, draw new terminal/desktop UI, or replace
a built-in feature outright (the built-in `/diff` now ships as a mod). Multiple mods
stack and respond to the same event in sequence.
**Pattern:** lifecycle-hook automation evolving into a full behavior-override layer.
**Parity impact:** gooseherd's Hooks row was marked ❌ — that was wrong. `crates/goose/src/hooks/mod.rs`
already implements the Open Plugins hooks spec (landed 2026-07-03, just before the last
review). Corrected to ✅, but the real gap moved up a level: gooseherd has no mods-equivalent
(UI replacement, prompt rewriting, stacked interception).

### 4. Ultracode / Dynamic Workflows (effort-level toggle change confirms this is now a first-class mode, not a side experiment)
`/effort ultracode` (or an inline `ultracode: ...` prompt) has Claude write a JS orchestration
script — `phase()`, `pipeline()`, `parallel()`, per-step `agent()` calls with schema-validated
results — that a runtime executes in the background, decoupled from the conversation, fanning
out up to 16 concurrent agents (1000/run).
**Pattern:** scripted, schema-verified multi-agent fan-out as a generic primitive, not a fixed
pipeline shape.
**Parity impact:** **this is the gap.** gooseherd has two fixed shapes — `/orch` (sequential
plan→implement→gates→review) and `/arena` (blind N-way parallel comparison) — but nothing
where the planner can author an arbitrary DAG of phases with mixed parallel/sequential steps
and machine-checked (schema-validated) subagent outputs at each step. New row added under
Loop primitives.

## Pick of the week

**Highest-leverage gap: scripted multi-agent fan-out with schema-validated steps (Ultracode/Dynamic
Workflows parity).**

Ready-to-run `/orch` task description:

> Add a `goose orch --script <file>` (or equivalent `/orch` mode) that accepts a declarative
> workflow definition — ordered/parallel phases, each phase a list of subagent calls with a
> required output schema — and executes it against the existing role/model-routing and
> `orch_ledger.jsonl` accounting, falling back cleanly to today's fixed plan→implement→review
> pipeline when no script is given. Success criterion: a sample workflow with 3 phases (2
> parallel read-only exploration agents → 1 implementer → 1 schema-validated reviewer) runs
> end-to-end and produces a ledger entry per agent call, with zero changes to existing `/orch`
> and `/arena` behavior when invoked without `--script` (verified by the existing orchestrate
> test suite passing unmodified, i.e. `cargo test -p goose-cli orchestrate:: ` reporting the
> same pass count before and after).
