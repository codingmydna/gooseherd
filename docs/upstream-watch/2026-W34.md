## Pick of the week

**Gap:** gooseherd has no way for two independently-running agents to talk to each other mid-task. `/orch` and `/arena` both coordinate roles *within* a single run (shared workspace, ledger, sequential phases); there's no addressable-session, message-passing primitive like CC's new `SendMessage`. This matters specifically for gooseherd because its whole premise is running multiple models concurrently (arena legs, orch roles) — right now they're blind to each other except through the filesystem and the ledger, which is coordination via side-channel, not by design.

**Ready-to-run `/orch` task:**

> Add a lightweight message-passing primitive between concurrently-running gooseherd sessions, addressable by session name — modeled on Claude Code's `SendMessage`/`@`-mention primitive (CHANGELOG v2.1.232). Scope: a session can call a new tool/command naming another live session (e.g. an `/arena` leg or a background `/orch` run) and post it a short text message; the receiving session surfaces the message at its next turn boundary. Success criterion: a new integration test starts two gooseherd sessions, sends a message from session A naming session B, and asserts session B receives and displays the message within 2 turns (or 5 seconds, whichever first), passing on **20/20 consecutive runs** with zero flakes.
